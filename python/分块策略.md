1. SPM中存储的IFM的HW越大，复用IFM（卷积的overlap）其中W越大还能复用axi burst（限制，W<=8，burst最大长度为256），H越大可减少mvin指令数量
2. SPM中存储的IFM的Cin越大，复用SA（但是目前不起效，一次只计算32个channel），还有好处是减少ACC中的数据量
3. ACC的HW维度：复用权重，减少权重重复搬运的次数
4. ACC的Cout维度复用IFM，但是会增大ACC中需要存储的数据量：有一点问题，搬出的时候需要先搬到spm量化为int8，如果多个cout就导致卷积的结果数量大于输入数量，需要更新建模，


参数定义：
1. 理论上的卷积存在这些参数：H，W，Cin，Cout，K
2. 软件根据SPM、ACC的大小探索出一个能够放得下的延迟最短的子张量，这是第一次分块。
3. 软件探索出来的分块策略会得到一个t_H*t_W*t_Cin*t_Cout的子张量，每次计算一个这么大的子张量，搬运对应的IFM，weight，bias，计算
4. 一个子张量计算完成后首先切换Cin，也就是每次先H、W、Cout不变，对应的Cin增加t_Cin，直到把所有的Cin算完，这样 ACC中的的OFM就是最终结果，可以搬出，后面切换H、W、Cout理论上没区别，但是考虑到输出张量的连续性，先切换W，再切换H，最后切换Cout
阶段性总结：
void conv()
{
    for (i_Cout=0;i_Cout<Cout;i_Cout+=t_Cout)
    {
        for(i_H=0;i_H<Hout;i_H+=t_H)
        {
            for(i_W=0;i_W<Wout;i_W+=t_W)
            {
                for(i_Cin=0;i_Cin<Cin;i_Cin+=t_Cin)
                {
                    // Tile convolution computation for tile (i_Cout,i_H,i_W,i_Cin)
                    // Tile size is (t_Cout,t_H,t_W,t_Cin)
                    // 这里还没有做mvin和mvout操作，IFM和weight的mvin都在conv_tile里面,mvout只会mvoutacc中的累加完成的结果，conv_tile中不会mvout
                    conv_tile();
                }
                // // 遍历完成cin后，acc中的结果已经累加完成，搬出
                // // tile ofm的大小是 (t_Cout/32,t_H,t_W,32)
                // mvout_tile_ofm_from_acc();
                // 注意，这里理解有误， 结果要先量化回spm再搬出来
            }
        }
    }
}


下面进入第二阶段，针对每个子张量进行进一步分块：

5. 对于每一个子张量，需要计算(t_Cout,t_H,t_W,t_Cin)大小的卷积
6. 由于目前dma，脉动阵列一次性只能处理32个channel的数据，t_Cin和t_Cout可能大于32（一般为32的倍数），所以conv_tile中需要继续分块
7. mvin操作需要分块，每切换32个channel就要新的一次mvin（对于nchwc32），考虑实现一个封装好的mvin，能够支持任意的channel


目前卷积的分块伪代码：

void conv_tile()
{
    //搬入tile ifm到sram, 最基本的mvin只能搬运(t_H,t_H,32)的tile,这里的t_Cin可能大于32，
    //需要循环搬运，里提供一个封装好的runtime接口，可以支持任意t_Cin的搬运
    mvin_tile_ifm_to_sram();

    //weight的排布可以编译时改变，在内存中的布局应该是（Cout/32，Cin/32，Kh，Kw， Cin32， Cout32）
    // 以二维的视角理解以方便mvin：对应的二维矩阵的n_col_num = Cin/32*Kh*Kw*Cin32*Cout32, n_row_num = Cout/32. n_col_num将会是mvin的stride（这个stride将会很大，超过了目前的寄存器位宽，正在修改寄存器）
    //每次conv_tile的Cout Cin可能大于32，所以一次需要搬运（t_Cout/32，t_Cin/32， Kh, Kw, Cin32, Cout32）的权重tile到sram
    //这个mvin可以一次性搬完，配置的参数为n_row_num = t_Cout, n_col_num = t_Cin/32 * Kh * Kw * Cin32 * Cout32
    mvin_tile_weight_to_sram();

    //以上的操作是将需要的数据一次性全部般进spm，后面如果实现了访存和计算并行则需要拆分

    // 下面的顺序只要保证Cout在最外面就行了，里面的顺序不影响性能
    for(j_Cout=0;j_Cout<t_Cout;j_Cout+=32)
    {
        // 每次切换Cout时需要mvin新的bias到acc的寄存器
        mvin_bias();
        for(j_H=0;j_H<t_H;j_H+=t_Hm)
        {
            for(j_W=0;j_W<t_W;j_W+=t_Wm)
            {
                for(j_Cin=0;j_Cin<t_Cin;j_Cin+=32)
                {
                    //计算tile (j_Cout,j_H,j_W,j_Cin)
                    //tile大小是(32,t_Hm,t_Wm,32)
                    //这里的t_Hm和t_Wm时根据OFM反推的，SA要求一次计算输出32个OFM像素，
                    //所以在kernel是3*3，stride=1的情况下 (t_Hm - 3 +1)*(t_Wm -3 +1) =32

                    //这里还需要判断，如果j_Cin==0，则是第一次计算，需要累加bias，否则是累加psum
                    //另外还需要判断是否是最后一次计算，如果是最后一次计算，还需要判断是否relu，并且配置量化参数，配置写回spm
                    //这需要确定写回SPM的哪里，这里需要修改分块策略，目前的分块策略会让IFM填满SPM，没有量化后写OFM回SPM的空间
                    //暂时修改分块策略，留出空间给OFM，后面考虑增加指令：量化ACC的数据写回SPM,
                    //这样的话，等计算完成后，SPM中的数据已经没用了，可以一次性从ACC量化到SPM中
                    //所以如果是最后一次计算，compute_tile需要指定relu和量化写回
                    //如何判断是最后一次计算？cin到最后一次时，j_Cin +32 >= t_Cin
                    if(j_Cin==0)
                        compute_tile(j_Cout,j_H,j_W,j_Cin);//is_bias=1
                    else
                        compute_tile(j_Cout,j_H,j_W,j_Cin);//is_bias=0
                }
            }
        }
    }
}
